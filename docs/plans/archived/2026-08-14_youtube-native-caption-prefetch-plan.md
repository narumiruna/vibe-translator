# YouTube Native Caption Prefetch Plan

## Goal

Use the exact runtime timed-text request URL generated by YouTube’s native player when the advertised Web caption `baseUrl` is not independently fetchable, while preserving the existing visible-caption fallback.

## Context

Live research on `HI2q3ci3Iuc` confirmed that the advertised Web track returned HTTP 200 with an empty body, while YouTube’s native request added runtime proof/client parameters and an Android VR player URL returned 427,824 bytes with 1,480 JSON3 events.

## Architecture

- The main-world caption probe observes bounded same-origin `/api/timedtext` resource URLs after enabling captions.
- The background validates and selects only a current YouTube timed-text URL matching the advertised video, language, and track kind.
- Prefetch uses the selected native request URL internally without exposing its proof token or full URL in diagnostics.
- The existing advertised track URL and progressive visible-caption path remain fallbacks.

## Risks

- YouTube resource timing may omit or delay the native request URL, so capture must be bounded and optional.
- Native request URLs contain short-lived proof tokens and must never be logged, persisted, or copied into diagnostics.
- YouTube may change its internal caption request shape, so selection must reject unrelated or cross-origin URLs safely.
